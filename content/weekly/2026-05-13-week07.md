## 本周进展

### Qt for Android 适配与问题修复 (gtanzhuo)

- ✅ **Qt 6.11 → 6.8.3 版本降级适配**
  - 原因: Qt 6.11 与 NDK r27c 存在 ABI 兼容问题，部分 `libc++_shared.so` 符号缺失导致链接失败
  - 降级至 Qt 6.8.3 LTS 版本，编译通过
  - 更新项目 `.pro` 文件: Qt5 `QT += quickwidgets` → Qt6 `QT += widgets + QQuickWidget`
- ✅ **NDK r27c 编译环境完整配置**
  - 配置 `android_arm64_v8a` 工具链
  - qmake 命令: `qmake6 -qtconf android_arm64_v8a/bin/target_qt.conf -spec android-clang`
  - JDK 由 11 升级至 OpenJDK 17 (Qt 6.8 要求)
- ✅ **Redmi Android 15 无障碍服务闪退修复**
  - 现象: 小米 (Redmi) 设备 Android 15 上 AccessibilityService 概率性崩溃
  - 根因: `onAccessibilityEvent` 回调中同步执行耗时操作 → 主线程 ANR (5秒超时) → 系统 kill 进程
  - 修复: 将耗时逻辑移至后台协程 (`Dispatchers.IO`)，回调中仅做事件分发
- ✅ **无障碍服务死锁根因分析与解决**
  - `AccessibilityService.onServiceConnected` 与 `onAccessibilityEvent` 之间存在双向锁竞争
  - 改用 `ConcurrentHashMap` + `AtomicBoolean` 替代 `synchronized` 同步块
- ✅ 编写一键编译部署脚本，支持 `adb install` 自动推送到设备

### Qt 组件兼容性测试 (canzhuo)

- ✅ Qt 6.8.3 全部 UI 组件在 Android 上的兼容性验证

### 树莓派统一控制中心 v3.0.0 (Raspberry Pi 后端)

- ✅ **搭建 FastAPI 后端服务** (监听端口 `:5003`)
  ```
  客户端 → HTTP :5003 → FastAPI ─┬─ GPIO (引脚22/27, BCM编号)
                                 ├─ PELCO-D 云台 (RS-485 /dev/ttySC0)
                                 ├─ 音频 (USB声卡 + WebSocket PCM流)
                                 └─ 海康摄像头 (TCP :9988 → C++ ptz_server → SDK → MJPEG :9990)
  ```
- ✅ **GPIO 控制模块** (`/api/gpio/*`) — 4 个端点
  - `GET /api/gpio/status` — 获取全部引脚状态
  - `GET /api/gpio/{pin}` — 获取单个引脚 (pin ∈ {22, 27})
  - `POST /api/gpio/{pin}/on` / `off` — 高/低电平输出控制
- ✅ **PELCO-D 云台控制** (`/api/ptz/*`) — 9 个端点
  - 硬件: RS-485 串口 `/dev/ttySC0`, 波特率 9600, 地址 1
  - `POST /api/ptz/connect` / `disconnect` — 串口连接管理
  - `POST /api/ptz/control` — 统一控制: `{"action": "up|down|left|right|stop|zoom_in|zoom_out"}`
  - `POST /api/ptz/preset` — 预置位: `{"action": "set|call|clear", "preset_num": 1}`
  - `POST /api/ptz/pan_tilt` — 方向速度控制: `{"pan_speed": 0, "tilt_speed": 100}`
  - `POST /api/ptz/aux` — 辅助功能 (雨刷等)
  - `POST /api/ptz/raw` — 原始十六进制 PELCO-D 命令
- ✅ **音频模块** (`/api/audio/*`) — 5 个端点
  - USB 声卡设备检测与选择 (`plughw:3,0`)
  - ALSA `aplay` 播放 + WebSocket 实时 PCM 音频流推送
  - 音量控制 (0.0 ~ 1.0)
- ✅ **海康摄像头模块** (`/api/camera/*`) — 13 个端点
  - 状态查询、PTZ 控制、预置位管理
  - 巡检点管理 (增删改查 + 排序)
  - 巡航扫描 (开始/停止)
  - 拍照快照 (JPEG)
  - MJPEG 实时视频流 (端口 `:9990`)

### 云台 APP (ysd_yuntaifb)

- ✅ **API Bearer Token 认证实现**
  - HTTP 请求头: `Authorization: Bearer {token}`
  - Token 过期自动刷新机制
  - 使用 Qt `QNetworkAccessManager` + `QNetworkRequest::setRawHeader`
- ✅ **建图图片 data:URI 格式适配**
  - 问题: Android 沙箱限制, QML 中 `file://` URL 无法访问应用私有目录
  - 解决: 服务端返回图片 Base64 编码, 客户端直接构造 `data:image/png;base64,...`
  - QML 用法: `Image { source: robotAPI.mapImageUrl }` 无需文件 I/O
- ✅ **界面重构**
  - 统一 Qt6 Material 设计风格
  - QML 组件化拆分: 设备状态面板、地图显示区、控制栏独立组件

### API 调试踩坑记录

| # | 现象 | 根因 | 解决方法 |
|---|------|------|----------|
| 1 | HTTP 400 Bad Request | POST 请求空 body 但设置了 `Content-Type: application/json` | GET/空 body POST 不设 Content-Type |
| 2 | HTTP 401 Unauthorized | Token 缺少 `Bearer ` 前缀 | 逐个格式用 curl 对比验证 |
| 3 | HTTP 405 Method Not Allowed | `async_stop_scan_map` 用 POST 实际接口只接受 GET | `curl -X GET` vs `-X POST` 对比 |
| 4 | 建图图片无法在 QML 显示 | `file://` 协议 Android 沙箱限制 | 改用 data:URI (Base64 内嵌) |
| 5 | Release 版日志无输出 | `qDebug()` 被 `-DQT_NO_DEBUG` 编译移除 | 改用 `qWarning()` 或 `__android_log_print` |

> **调试原则**: 始终先用 `curl` 在 PC 上逐接口验证 HTTP 方法和返回格式，确认无误后再编写 C++ 代码。
